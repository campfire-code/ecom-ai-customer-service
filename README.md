# 多平台 AI 客服

> 篝火出品 · 收录于篝火 App 应用区

> [!WARNING]
> 本工具涉及第三方平台的自动化或内容获取，存在账号被限制、违反平台规则或侵权的风险，仅供学习研究。请遵守平台规则与法律法规，使用后果自负。

**半自动**的电商 AI 客服助手：把顾客的问题粘贴进来，先在你自己维护的店铺知识库里查资料，再让大模型起草 1～3 条候选回复，一键复制后由你**手动**粘贴发送。

- 不自动操作任何平台客户端、不读 cookie、不注入，封号风险比「自动回复」类工具低得多（但回复内容仍须符合平台规则，由你负责）。
- 知识库按店铺分组，支持导入 Markdown / Excel / CSV / 纯文本。
- 只依据知识库回答；资料里没有时明确提示「资料里没有」并给出转人工话术，不编造价格、库存、物流时效。
- 回复里出现「最低价」「全网最」「保证」等绝对化用语时标黄提醒（词表可编辑，示例词表，以平台规则为准）；回复里的数字在资料里找不到时也会提醒核对。
- 大模型由你在「设置」里填写（兼容 OpenAI 接口的地址、密钥、模型名），密钥只保存在本机。顾客的问题和命中的资料会发送给你填的大模型服务。

> 独立实现：本工具的代码由篝火从零编写（MIT），没有使用、参考或改写任何同类开源项目的代码。

## 怎么用

1. 首次打开：到右上角「设置」填好大模型的接口地址、密钥和模型名。
2. 「知识库」页：现在是内置的虚构示例资料，可以点「删除全部示例」，再「新增」或「导入」你自己的商品资料、售后政策、常见问答（也可以把文件拖进窗口）。先在右上的「店铺」里选好或「新建店铺」，导入的文件会归到当前店铺；两个店铺都适用的资料，新增时选「通用」。
3. 导入格式：
   - Markdown：`# 分类`、`## 条目标题` + 正文；没有二级标题时每个一级标题是一条。
   - 纯文本：空行分段；支持「问：…答：…」。
   - Excel / CSV：表头认「店铺、分类、标题（或问题）、内容（或回答）、关键词」，顺序任意。关键词写顾客可能的别称（如「水杯、杯子」），能让资料更容易被查到。
4. 「回复」页：粘贴顾客的话（一句或一段聊天记录；带「顾客：」「客服：」前缀时只取顾客说的话），选语气和候选条数，点「生成回复」。
5. 看候选回复下面标出的引用资料；黄色提示要先处理；满意的点「复制」，到平台客服窗口粘贴并人工确认后发送。
6. 「敏感词」页：按所在平台的最新规则增删词表。

**已知限制**：检索是关键词匹配（不是语义检索），顾客用了资料里没有的说法时可能查不到，请用「关键词」字段补充别称；数字核对只检查阿拉伯数字。

## 验收用例

以下用例不需要大模型，用 `samples/` 里的文件操作（大模型相关的流程用假函数在 `pnpm test` 里验证，真实接口联调待补）。

1. 打开后「知识库」页点「删除全部示例」，右上店铺选「新建店铺」建一个「示例店铺 · 家居」。
2. 依次导入 `samples/示例资料.md`、`示例问答.txt`、`示例资料.csv`、`示例资料.xlsx`。应依次提示：导入 4 条；导入 2 条；导入 3 条；导入 1 条（2 条重复已跳过）。
3. 「回复」页粘贴 `samples/示例聊天记录.txt` 的内容，填好大模型后点「生成回复」：应出现 1～3 条候选，每条标出引用的「陶瓷马克杯 B 款」；价格 39 元、350ml 只能来自资料。
4. 粘贴 `samples/示例聊天-资料里没有.txt`（问线下门店）并生成：应显示「资料里没有」和转人工话术，且**不会调用大模型**。
5. 把候选回复里手动改成含「全网最低价」，或在假大模型测试里观察：含词表内用语的候选会标黄；回复里出现资料没有的数字会提示核对。
6. 「敏感词」页删掉一个词保存，重新打开应用后词表保持修改。

## 自己编译

需要 Node.js 22、pnpm、Rust。

```bash
pnpm install
pnpm test          # 单元测试
pnpm tauri dev     # 开发运行
pnpm tauri build   # 打包
```

界面框架在 `src/kit`（所有 campfire-code 工具共用），本工具的逻辑在 `src/tool`。
